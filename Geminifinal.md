Это задача **Level 4 (System Architecture Blueprint)**. Я создам исчерпывающий документ, который описывает **всю систему**, её компоненты, потоки данных и правила. Этот документ можно будет использовать для передачи проекта другой команде, другой нейросети или для восстановления системы с нуля.

Я разделю его на логические блоки.

---

### Промпт для другой нейросети: "Полное описание проекта ЯГК Schedule"

**Цель:** Восстановить или доработать систему "ЯГК Schedule" — веб-сайт и Telegram-бот для просмотра расписания Ярославского градостроительного колледжа с учетом ежедневных замен.

**Стек технологий:**
*   **Backend:** Python 3.10+, Starlette, Uvicorn, SQLAlchemy (асинхронно с `aiosqlite`).
*   **Frontend:** HTML5, Tailwind CSS (через CDN), JavaScript (Vanilla).
*   **База данных:** SQLite (файл `ygk.db`).
*   **Бот:** `python-telegram-bot` (Polling).
*   **Инфраструктура:** Linux-сервер (Ubuntu/Debian) с `systemd` для управления процессами.

---

### 1. Архитектура и компоненты

Проект состоит из трех основных Python-модулей, работающих вместе:

1.  **`core.py` (Ядро/Мозг):**
    *   **Ответственность:** Вся логика, связанная с получением и обработкой расписания. Не зависит от Telegram или Web.
    *   **Входные данные:**
        *   `schedule.json`: Статичная база расписания.
        *   HTML-страницы с сайта колледжа (замены).
    *   **Выходные данные:** Python-объекты `DaySchedule` и `Lesson`, типизированные через `Pydantic`.
    *   **Ключевая логика:**
        *   **`update_replacements()`**: Асинхронно скачивает HTML, парсит его **строго** по 6 колонкам (`<td>`), извлекает дату и возвращает список замен и флаг `is_changed`.
        *   **`get_schedule()`**: Принимает `group_name` и `date`. Сначала берет базу из `schedule.json`, фильтрует по типу недели, а затем **накладывает** замены из кэша, если даты совпадают. Корректно обрабатывает группы со слэшем (`ИС1-11/ИС1-12`).

2.  **`database.py` (Память):**
    *   **Ответственность:** Всё взаимодействие с базой данных `ygk.db`.
    *   **Технология:** SQLAlchemy 2.0 (asyncio) + `aiosqlite`.
    *   **Таблицы (ORM Модели):**
        *   `User`: Хранит `telegram_id`, `username`, `group_name`, `role` ('student'/'headman'/'admin'), флаги `is_active` и `last_notify_date` (для защиты от спама).
        *   `GroupSettings`: Настройки для каждой группы (`hw_enabled`, `autoset_enabled`).
        *   `GroupPin`: PIN-коды для доступа к панелям старост.
        *   `Student`: Список студентов группы для системы дежурств (ФИО, username, `telegram_id` (если привязан)).
        *   `Homework`: Записи о домашнем задании (привязаны к группе, дате и **предмету**).
    *   **Ключевая логика:** Все методы строго асинхронные. Реализованы `Upsert`-операции (создать, если нет, или обновить).

3.  **`bot_main.py` (Интерфейс: Telegram):**
    *   **Ответственность:** Обработка команд и сообщений от пользователей в Telegram.
    *   **Внешний вид (UI/UX):**
        *   **Клавиатура:** `ReplyKeyboardMarkup` (кнопки внизу экрана): "Сегодня", "Завтра", "Неделя", "Группа", "Настройки".
        *   **Формат сообщений:** Строгий, с эмодзи-цифрами (0️⃣, 1️⃣...). `📅 День (дата | числитель/знаменатель) \n 🔄 1️⃣ Предмет - Кабинет \n 📚 ДЗ: ...`.
    *   **Ключевая логика:**
        *   **Middleware (`subscription_middleware`):** Перехватывает все сообщения в ЛС. Если пользователь не подписан на каналы из `REQUIRED_CHANNELS`, блокирует дальнейшую работу и показывает кнопки подписки.
        *   **`ConversationHandler`:** Реализует диалоги для выбора группы и ввода имени. Везде есть **умный поиск** (предлагает варианты, если ввод неточный).
        *   **`JobQueue` (Планировщик):**
            *   `job_smart_poll`: В 12:05 начинает проверять замены. Если их нет — перезапускает себя каждые 10 минут до 19:00.
            *   `broadcast_updates`: Рассылает уведомления с **полным текстом расписания** тем, кто еще не получал сегодня.
            *   `job_autoset_duty`: В 14:00 назначает дежурных.
            *   `job_check_duty`: В 17:00 пинает старост, если ДЗ не заполнено.
            *   `job_reset_sick`: Ночью сбрасывает флаги "болеет".
        *   **Deep Linking:** Обрабатывает ссылки `t.me/bot?start=setgroup_...`.

4.  **`web_main.py` (Интерфейс: Сайт и API):**
    *   **Ответственность:** Отображение расписания в браузере и предоставление API для Mini Apps.
    *   **Внешний вид (UI/UX):**
        *   **`schedule_view_template.html`:** Навигация по дням и неделям (стрелки `←`, `→`), кнопка "Избранное" (⭐), плавающая кнопка "Заполнить ДЗ" (✏️), кнопка "Установить в боте" (🤖).
        *   **Mini Apps (`homework_form.html`, `headman_panel.html`):** Вход по **PIN-коду**. Интерфейс адаптирован под темную/светлую тему Telegram, исправлены цвета (принудительно черный текст на белом фоне).
    *   **API:**
        *   `/api/homework`, `/api/headman/...`: Принимают JSON, проверяют PIN-код и взаимодействуют с `database.py`.
        *   `/api/get_subjects`: Отдает список предметов на дату для формы ДЗ.
        *   `/api/headman/notify`: Отправляет сообщение в Telegram через `httpx`.
        *   `/api/kwgt/schedule/...`: Отдает текст с `<br>` для виджетов.

5.  **Скрипты:**
    *   `migrate.py`: Обновляет схему SQLite без потери данных (добавляет новые таблицы и колонки).
    *   `csv_parser.py`: Конвертирует Excel/CSV в `schedule.json`, понимая логику "верхняя строка = четная, нижняя = нечетная".

### 2. Важные данные и конфигурация

*   **`TOKEN` (в `bot_main.py` и `web_main.py`):** Токен Telegram бота.
*   **`ADMIN_ID` (в `bot_main.py`):** Твой Telegram ID для доступа к админ-командам.
*   **`REQUIRED_CHANNELS` (в `bot_main.py`):** Список каналов для обязательной подписки (например, `["@my_channel"]`).
*   **`DATABASE_URL` (в `database.py`):** Путь к файлу базы данных, `sqlite+aiosqlite:///ygk.db`.
*   **`SCHEDULE_FILE` (в `core.py`):** Имя файла с базовым расписанием.
*   **`REPLACEMENTS_URLS` (в `core.py`):** Ссылки на страницы замен.
*   **`BOT_USERNAME` (в `web_main.py`):** Юзернейм бота без `@` для Deep Link ссылок.

### 3. Гайд по деплою и управлению

1.  **Настройка сервера:** Ubuntu/Debian. Установить Python 3.10+, `pip`, `sqlite3`.
2.  **Swap:** Обязательно включить Swap-файл (минимум 2 ГБ), если ОЗУ мало.
3.  **Загрузка файлов:** Скопировать все файлы проекта в `/root/ygk_project/`.
4.  **Установка библиотек:** `pip3 install -r requirements.txt`.
5.  **Миграция БД:** `python3 migrate.py`.
6.  **Настройка `systemd`:** Создать два сервиса (`ygk-bot.service`, `ygk-web.service`), указав правильные пути к `WorkingDirectory` и `ExecStart`.
7.  **Запуск:** `sudo systemctl daemon-reload && sudo systemctl enable --now ygk-bot ygk-web`.
8.  **Логи:** `journalctl -u ygk-bot -f` и `journalctl -u ygk-web -f`.

**Если я переезжаю на хостинг с 8GB RAM, мне нужно что-то менять?**
Да. Это открывает возможность для **Level 4** апгрейда.
*   **База данных:** Можно перейти с SQLite на **PostgreSQL**. Это повысит производительность под высокой нагрузкой. Тебе нужно будет:
    1.  Установить `postgresql` на сервер.
    2.  Установить библиотеку `pip install asyncpg`.
    3.  В `database.py` поменять `DATABASE_URL` на `postgresql+asyncpg://user:pass@localhost/db_name`.
    4.  Перенести данные из SQLite в Postgres (есть специальные утилиты).
